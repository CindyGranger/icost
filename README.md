# 账单整理器（手机优先 MVP）

这是一个可自托管的移动网页/PWA：微信 CSV/XLSX 在浏览器本地解析。只处理交易类型严格等于“商户消费”或“二维码付款”的支出；其他交易保留原始字段、原样导出，不调用模型。分类建议写入符合条件交易的备注列。导出仍是微信原始账单列格式，不是 iCost 模板。

## 快速启动

需要 Node.js 18 或更新版本，不需要安装 npm 依赖。

```sh
cd outputs
LLM_API_KEY='你的模型服务密钥' LLM_MODEL='gpt-4o-mini' node server.mjs
```

可设置 `LLM_API_URL` 指向兼容 OpenAI Chat Completions 的接口地址；`PORT` 默认 8787，服务默认只监听本机 `127.0.0.1`。部署到托管平台时设置 `HOST=0.0.0.0`。不开模型也能使用本地明确规则和手动分类：启动后在设置里关闭模型分类即可。请勿把服务端口直接暴露到公网；正式部署应使用支持 HTTPS 的托管平台，并将密钥添加到平台的服务端环境变量。

## iPhone 使用/部署

1. 将 `outputs` 目录部署到支持 Node.js 的 HTTPS 主机（如自有 VPS 或 Node 应用托管服务），启动命令为 `node server.mjs`，并配置 `LLM_API_KEY`、可选 `LLM_MODEL` 和 `LLM_API_URL`。
2. 在 iPhone Safari 打开 HTTPS 服务地址。网页会对同源 `/api/classify` 发出 POST。若直接从本地 `file://` 打开页面，默认会 POST 到 `http://127.0.0.1:8787/api/classify`，因此需先在该电脑启动本地服务；手机端应访问 HTTPS 部署地址。密钥只配置在服务端环境变量。
3. Safari 分享菜单选择“添加到主屏幕”。微信账单从微信保存到“文件”后，在应用中选取 CSV/XLSX。
4. 审核待确认项；导出 CSV 后会保留微信原始表头和行数据，分类建议追加在备注字段中。此文件不是 iCost 模板文件。

直接用浏览器打开 `index.html`（`file://`）时，页面默认把符合条件的交易请求发送到本机 `127.0.0.1:8787`，需先运行带 `LLM_API_KEY` 的服务端。也可通过 `node server.mjs` 打开 `http://localhost:8787`，或在手机上使用 HTTPS 部署。

本 MVP 的文件解析和确定规则分类均在设备上进行。模型调用会发送商户、商品、交易类型、金额、备注和批次内序号；日期、交易单号及原始完整账单不会发送。模型服务商仍可能按其服务条款处理请求内容。

## 从旧版更新

请更新前端 `index.html`、`app.js` 和 `sw.js` 后刷新页面。页面标题会显示 `微信账单整理器 v6`，导出文件名为 `wechat_classified_v1.csv`。不要用本目录覆盖你自行修改过的 `server.mjs`。

## 当前处理规则

- 不删除文件内重复行，所有原始交易行均保留。
- 仅交易类型为“商户消费”或“二维码付款”、且不是收入/退款/转账/红包的行进入分类流程。
- 未处理行保持原始字段。自动分类和人工确认的分类建议追加到原行的备注字段。
- 导出使用输入账单的原始表头顺序、微信原始列和 CSV 格式。
- 微信 XLSX 解析库通过 jsDelivr 加载；首次打开需联网。主界面和核心脚本可缓存用于再次访问，模型请求仍需联网。

## 文件

- `index.html`, `style.css`, `app.js`: 移动端 PWA
- `server.mjs`: 静态文件服务和 LLM 代理
- `manifest.json`, `sw.js`: 主屏幕安装与基础缓存
