# 账单整理器（手机优先 MVP）

这是一个可自托管的移动网页/PWA：微信 CSV/XLSX 在手机浏览器本地解析，明确规则先本地处理；其余消费摘要以最多 30 笔一批发给自建服务端的轻量模型代理。API 密钥只存在服务端环境变量。应用不保留历史账单或分类学习数据。

## 快速启动

需要 Node.js 18 或更新版本，不需要安装 npm 依赖。

```sh
cd outputs
LLM_API_KEY='你的模型服务密钥' LLM_MODEL='gpt-4o-mini' node server.mjs
```

可设置 `LLM_API_URL` 指向兼容 OpenAI Chat Completions 的接口地址；`PORT` 默认 8787。不开模型也能使用本地明确规则和手动分类：启动后在设置里关闭模型分类即可。请勿把服务端口直接暴露到公网；正式部署应使用支持 HTTPS 的托管平台，并将密钥添加到平台的服务端环境变量。

## iPhone 使用/部署

1. 将 `outputs` 目录部署到支持 Node.js 的 HTTPS 主机（如自有 VPS 或 Node 应用托管服务），启动命令为 `node server.mjs`，并配置 `LLM_API_KEY`、可选 `LLM_MODEL` 和 `LLM_API_URL`。
2. 在 iPhone Safari 打开服务地址。模型服务地址默认是同源 `/api/classify`。如果使用独立后端，再在“设置”中填入其 HTTPS 地址。密钥绝不输入网页。
3. Safari 分享菜单选择“添加到主屏幕”。微信账单从微信保存到“文件”后，在应用中选取 CSV/XLSX。
4. 审核待确认项；导出 CSV 后，在 iOS 分享菜单保存到“文件”或交给 iCost。首次导入前，先在 iCost 当前版本的模板导入流程中核对列名、账户和分类名称。

本 MVP 的文件解析和确定规则分类均在设备上进行。模型调用会发送商户、商品、交易类型、金额、备注和批次内序号；日期、交易单号及原始完整账单不会发送。模型服务商仍可能按其服务条款处理请求内容。

## 从旧版更新

请把新版整个 `outputs` 目录重新部署到原来的 HTTPS 地址，至少覆盖 `index.html`、`app.js`、`style.css`、`sw.js` 和 `server.mjs`，然后重启 Node 服务。页面标题会显示 `账单整理器 v3`，新版 CSV 文件名为 `icost_import_v3.csv`。如果 iPhone 仍显示旧页面，请从主屏幕移除旧网页快捷方式，在 Safari 打开同一地址并刷新后，再重新添加到主屏幕；新版 service worker 会清理旧缓存。

## 当前处理规则

- 文件内按微信交易单号去重；无单号时按时间、商户、商品、金额、收支组合去重。没有跨周历史数据库，避免本地持久化保存完整交易记录。
- 退款、转账、红包和收入不进入消费 CSV，另可下载 `needs_separate_review.csv` 供人工处理。
- 模型置信度低于 0.60、输出类别不合法或模型明确要求确认的交易会进入逐笔确认；未确认交易不会导出。
- CSV 严格按 iCost 官方模板顺序输出：日期、类型、一级分类、二级分类、账户1、账户2、备注、金额、货币、标签。金额为纯数字，类型字段使用“支出”。官方模板说明要求保持表头字段顺序。
- 微信 XLSX 解析库通过 jsDelivr 加载；首次打开需联网。主界面和核心脚本可缓存用于再次访问，模型请求仍需联网。

## 文件

- `index.html`, `style.css`, `app.js`: 移动端 PWA
- `server.mjs`: 静态文件服务和 LLM 代理
- `manifest.json`, `sw.js`: 主屏幕安装与基础缓存
